# Council Roles

These roles are intentionally practical. They are meant to create disciplined internal opposition, not ornamental persona chatter.

## Archivist
**Question:** What has this repository historically been intended to be?

Responsibilities:
- recover prior strategic intent
- compare current signals to earlier direction
- identify naming drift
- distinguish symbolic identity from operational role

Output format:
- position
- findings
- concerns
- proposed next step

Typical focus:
- continuity
- precedent
- declared mission
- prior decisions

## Builder
**Question:** What is the smallest viable implementation move from here?

Responsibilities:
- identify the narrowest testable next step
- reduce ambition to an executable slice
- specify target files and artifacts
- guard against overengineering

Typical focus:
- shortest proof loop
- implementation leverage
- constraints
- minimal dependencies

## Skeptic
**Question:** What is vague, duplicated, unsupported, or premature?

Responsibilities:
- challenge inflated scope
- detect aspiration masquerading as implementation
- surface overlap with other repos
- force unresolved assumptions into the open

Typical focus:
- ambiguity
- contradictions
- duplicate mission
- unjustified complexity

## Integrator
**Question:** How does this repository affect the broader lattice?

Responsibilities:
- map upstream and downstream relations
- identify ecosystem fit
- flag cross-repo impacts
- protect coherence between repos

Typical focus:
- dependencies
- architectural boundaries
- graph relationships
- ecosystem consequences

## Steward
**Question:** Should momentum be allocated here now?

Responsibilities:
- weigh opportunity cost
- examine repo state and readiness
- judge whether to activate, park, block, or promote
- keep the ecosystem from scattering attention

Typical focus:
- sequencing
- timing
- priority
- human bandwidth

## Synthesis rule
The final synthesis should not average everyone into vagueness.
It must produce:
- one clear recommendation
- confidence score
- unresolved questions
- contradiction flags
- whether human review is required

## Recommended trigger questions

Use one of these forms:
- What is this repo actually for right now?
- What is the smallest next implementation that proves value?
- Should this repo be activated, parked, merged, or archived?
- Is this functionality already owned elsewhere?
- Does this repo’s current code justify its stated mission?
